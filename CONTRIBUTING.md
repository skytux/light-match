# Contributing to Light Match

Thanks for helping. There are two kinds of contribution: lamp profiles for
the shared database, and code.

## Lamp profiles

A lamp profile tells every Light Match user how to drive one lamp model so it
shows the shared reference space **lm-ref-1** (see
[docs/reference-space.md](docs/reference-space.md)). Profiles live in
`custom_components/light_match/profiles/<manufacturer>/<model>.json` and are
checked against `profiles/profile.schema.json`.

### Calibrating

1. Pick a reference lamp that shows lm-ref-1: a Philips Hue colour lamp with
   gamut C (White and Color Ambiance). Select it as the reference in the
   Light Match panel; the panel then sends it each cell's target.
   Calibrations against any other lamp get the target `house`: fine for your
   home, but the database only takes `lm-ref-1` profiles.
2. Set up the phone screen (it shows the swatch): colour mode Natural or
   sRGB, night mode / blue-light filter, enhanced contrast, adaptive colour,
   True Tone, eye comfort and HDR boost all off, a screen with good colour
   rendering (AMOLED preferred). Press **Match screen to lamp** and set the
   phone brightness so its white patch matches the lamp at 100 %, with
   auto-brightness off; keep it there for the whole session. Then tick *I
   calibrated under these conditions*: the profile gets
   `calibration.screen_conditions_confirmed: true`, a **good practice** badge
   in the panel and the index, and a small ranking boost (worth one thumbs
   up).
3. Put the two lamps side by side, ideally shining on the same white wall,
   in a dark room, with the same diffuser or shade (or none).
4. Start with the **quick 5-point mode**. Inference spreads those five cells
   over the grid; check the result and add cells where it is off.
5. For each cell, move the sliders until the lamp looks the same as the
   reference: first the colour, then the brightness. Look away for a moment
   between cells; eyes adapt.
6. Fill in the calibration details if you like (screen used, instrument,
   method, a note up to 500 characters). They go into the profile's
   `calibration` and `notes`.
7. Check a few targets between cells with the twin before sharing.

### Sharing

Use **Share profile** in the panel. It asks for an optional nickname, builds
the profile file (the lamp's model ids, firmware note, capabilities and your
cells) and opens a prefilled "New lamp profile" issue. If the profile is too
long for the link, it downloads the file and you attach it to the issue.
You may also open a pull request that adds the file.

### Checklist

- [ ] Target is `lm-ref-1`, calibrated against a gamut C Hue lamp.
- [ ] `device.manufacturer` and `device.models` match what Home Assistant
      shows on the device page; add every model id and product code you know
      the profile fits.
- [ ] `provenance.method` is honest: `by_eye`, `lux_meter` or `colorimeter`.
      Never mark a profile `verified` yourself: a maintainer does that after a
      second person confirms it.
- [ ] `provenance.notes` names the firmware and anything unusual (diffuser,
      a channel that rounds up, a floor that changes with colour).
- [ ] Capabilities you are sure of only (kelvin range, brightness floor,
      whether the lamp dims its channels at the floor). Leave out guesses.
- [ ] No personal data: no real name, email, entity ids, room names, IP or
      MAC addresses. The nickname is public.
- [ ] `python scripts/profiles.py check` passes (or the "Profiles" check on
      the pull request), and `python scripts/profiles.py index` was run.

### Nicknames

The `contributors` list holds a nickname, an optional GitHub login, a role
(`calibrated`, `measured`, `verified` or `edited`) and a date. A nickname is
optional and should not be your real name unless you want it public. Light
Match never adds your name or email anywhere.

### Licence

Profile data is licensed under
[CC BY 4.0](custom_components/light_match/profiles/LICENSE). Submitting a
profile (issue or pull request) means you agree to license it under CC BY 4.0;
credit is given through the nickname in the file.

Imported profiles (`profiles/imported/`) are generated by `tools/import/` from
public databases and keep those databases' MIT, BSD and Apache notices. Do
not edit them by hand: improve the source or the importer, or submit a
measured profile for the model instead; measured and verified profiles rank
above imported ones.

### Ratings and reports

Every profile has a Discussion in the "Lamp profiles" category. A thumbs up
or down there is its rating, shown in the panel next to the matched profile
(**Rate / report**). Tell in a comment whether it works for your lamp: model,
firmware and integration.

Maintainers: to enable 👍 / 👎 from inside the panel, register a GitHub OAuth
app (Settings → Developer settings → OAuth Apps → New; any homepage and
callback URL, e.g. the repository), tick **Enable Device Flow**, and put its
client id (not a secret) in `CLIENT_ID` in
`custom_components/light_match/github.py`. While it is empty the feature is
hidden. Users sign in with the device flow and the `public_repo` scope.

## Code

- Everything runs in containers; nothing is installed on the host:
  `./scripts/test.sh` runs ruff, the tests and the panel check.
- One version bump and one CHANGELOG entry per change (`VERSION` and
  `manifest.json`).
